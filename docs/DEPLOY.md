# פרסום LitReview כאתר — מדריך פריסה (M7)

המערכת היא **שרת אחד** שמגיש גם את ה-API וגם את ממשק המשתמש. כדי לפתוח אותה
לאינטרנט צריך שלושה דברים: (1) קוד גישה, (2) פלטפורמה שמריצה שרת Python
מתמשך, (3) דומיין. הכול ארוז כבר — נשארו רק הקליקים בפלטפורמה.

## מסלול 0 — שימוש אישי על מנוי Claude, בלי מפתח API (מצב native)

כלי לעצמך בלבד, על המחשב שלך: הממשק המלא בדפדפן, וסשן Claude Code רגיל
(על מנוי Claude — בלי חיוב API) הוא "המנוע" שעונה לצינור דרך גשר קבצים.
שני טרמינלים:

**טרמינל 1 — השרת והממשק:**

```bash
cd LitReview && pip install -e ".[server]"     # פעם אחת
SURVEY_LLM_BACKEND=native \
SURVEY_BRIDGE_TIMEOUT=3600 \
SURVEY_CONTACT_EMAIL=you@example.com \
python -m litreview.server --port 8000
# → http://127.0.0.1:8000  (מקומי — אין צורך בקוד גישה)
```

יוצרים סקר בדפדפן כרגיל; שערי האישור (תוכן עניינים / מקורות / טיוטה)
מטופלים בממשק. כשריצה מתחילה, מסך "ריצת המערכת" מציג פאנל 🔌 עם תיקיית
הגשר ופקודת שירות מוכנה להעתקה.

**טרמינל 2 — המנוע (בתיקיית הפרויקט):** מדביקים את הפקודה מהפאנל —
היא פותחת סשן Claude Code שקורא את `SKILL.md` ומשרת את הבקשות: כתיבת
הפרקים, עיגון הטענות, ומחקר העומק עם חיפוש web אמיתי. משאירים אותו פתוח
עד סוף הריצה.

**לתוצר איכותי מקסימלי** מוסיפים לטרמינל 1 את דגלי ההעמקה (כולם עובדים
במצב native; המחיר הוא זמן ריצה ושימוש במנוי, לא כסף לפי טוקן):

```bash
SURVEY_RELIABILITY_SIGNALS=1 \   # 9 אותות אמון לכל מקור מצוטט (מאגרים חינמיים)
SURVEY_DR_DEPTH=deep \           # מחקר web מעמיק: רדיפת מקורות ראשוניים, עדשות
SURVEY_SOURCE_SCOUT=1 \          # גילוי מאגרים ייעודיים כשיש פער כיסוי
SURVEY_MAX_FIX_ROUNDS=3          # יותר סבבי כתיבה↔ביקורת
# אופציונלי: SURVEY_DEPTH=practical (דוגמאות מחושבות) · SURVEY_ML_WEB=1 (רב-לשוני)
```

בהגדרת הסקר בוחרים היקף מלא (30–40 עמ') כשרוצים את המסמך העמוק ביותר.
הערה: ריצה נטושה באמצע ממשיכה מאותה נקודה ("המשך ריצה") — כל שלב שהושלם
לא רץ שוב, ותשובות גשר קודמות מוגשות מה-cache.

## 1) הרשאות — קוד גישה משותף

מגדירים משתנה סביבה `SURVEY_ACCESS_CODE` (קוד ארוך שקשה לנחש). מרגע שהוא
מוגדר:

- כל דף וכל קריאת API דורשים התחברות; מי שאינו מחובר מנותב ל-`/login.html`.
- ההתחברות יוצרת session חתום (עוגיית httpOnly) ל-30 יום.
- **החלפת הקוד מנתקת מיידית את כל המחוברים** — זה מנגנון ה"ביטול הרשאה"
  של מודל הקוד המשותף.
- הגנת ניסיונות: 10 קודים שגויים מאותה כתובת → נעילה לרבע שעה.

בלי המשתנה (ברירת המחדל) אין שום אימות — מצב שמתאים רק להרצה מקומית.

## 2) דרישות פרודקשן

| מה | למה |
|---|---|
| `ANTHROPIC_API_KEY` | סקרים אמיתיים רצים במצב `api` (כולל חיפוש web). מצב ה-native (גשר הקבצים) עובד רק ליד סשן Claude Code אינטראקטיבי — לא בשרת. **העלות האמיתית של הכלי היא שימוש ב-API לכל סקר, לא האירוח.** |
| `SURVEY_CONTACT_EMAIL` | ה-polite-pool של המאגרים האקדמיים (OpenAlex/Crossref). |
| Volume ל-`/app/var` | כל הסקרים, הגרסאות והפלטים נשמרים שם. בלי דיסק קבוע — הם נמחקים בכל ריסטרט/דיפלוי. |

## 3) איפה לארח

### ⚠️ למה לא Vercel (ולמה הדיפלוי שלו נכשל)

Vercel מריץ אתרים סטטיים ופונקציות קצרות-חיים ללא דיסק. LitReview הוא ההפך
הגמור: ריצת סקר היא **תהליך רקע של דקות ארוכות** (חיפוש ב-14 מאגרים, כתיבה,
לולאות תיקון), עם **SSE** לעדכונים חיים ו**אחסון על דיסק**. שלושתם לא
קיימים במודל של Vercel — ולכן הדיפלוי האוטומטי שנוצר כשהריפו חובר ל-Vercel
נכשל ותמיד ייכשל. מומלץ לנתק את האינטגרציה (בחשבון ה-Vercel: Project →
Settings → Git → Disconnect) כדי שה-❌ שלה לא יבלבל ב-PR.

### אפשרות א' — Render (מומלץ; אותה חוויה של "לחבר GitHub", יש מסלול חינם)

הריפו כולל `render.yaml`, אז זה Blueprint מוכן:

1. נרשמים ב-render.com ומחברים את חשבון ה-GitHub.
2. New → **Blueprint** → בוחרים את הריפו `LitReview` → Render קורא את
   `render.yaml` ובונה מה-Dockerfile.
3. בטופס שנפתח ממלאים את הסודות: `SURVEY_ACCESS_CODE`,
   `ANTHROPIC_API_KEY`, `SURVEY_CONTACT_EMAIL` → Apply.
4. אחרי הבנייה יש כתובת `https://litreview-XXXX.onrender.com` — עובדת מיד.
5. **דומיין משלך**: Settings → Custom Domains → מוסיפים
   `litreview.הדומיין-שלך.com`, ואצל רשם הדומיין יוצרים רשומת **CNAME**
   שמצביעה לכתובת ה-onrender. HTTPS אוטומטי.

מגבלות המסלול החינמי (כתובות גם ב-`render.yaml`):

- **שינה אחרי ~15 דקות ללא שימוש** — הבקשה הראשונה אחרי שינה איטית (עד
  דקה). למחקר פנימי זה בדרך כלל נסבל.
- **אין דיסק קבוע בחינם** — הסקרים השמורים נמחקים בכל דיפלוי/ריסטרט
  (את קבצי ה-HTML/DOCX מורידים ממילא). כשהכלי מוכיח את עצמו: שדרוג ל-plan
  `starter` (~7$/חודש) + ביטול ההערה על בלוק ה-`disk` ב-`render.yaml`
  נותן אחסון קבוע ובלי שינה.

### אפשרות ב' — שרת פרטי (VPS: Hetzner/DigitalOcean, ~5$/חודש)

שליטה מלאה ואחסון קבוע מהרגע הראשון:

```bash
git clone https://github.com/yaligolan27/LitReview && cd LitReview
cp .env.example .env && nano .env        # קוד גישה, מפתח API, DOMAIN
docker compose --profile domain up -d    # בונה, מריץ, ו-Caddy משיג HTTPS
```

אצל רשם הדומיין: רשומת **A** של `litreview.הדומיין.com` → כתובת ה-IP של
השרת. זהו — Caddy מנפיק ומחדש תעודות לבד.

בלי דומיין (לבדיקה): `docker compose up -d` → `http://<ip>:8000`.

### אפשרות ג' — חינם-באמת עם אחסון קבוע

Oracle Cloud Free Tier נותן VPS חינמי קבוע — ואז ממשיכים לפי אפשרות ב'.
ההרשמה מסורבלת יותר; מתאים אם גם 5-7$ לחודש הם מחוץ לתקציב.

## 4) תפעול

- **הרצה מקומית ללא Docker**: `SURVEY_ACCESS_CODE=... python -m litreview.server --port 8000`.
- **בדיקת חיים**: `GET /api/health` (פתוח ללא התחברות; משמש את הפלטפורמה).
- **גיבוי**: כל המצב הוא קבצי JSON תחת `var/` — ‏`tar czf backup.tgz var/`
  (ב-compose: ‏`docker compose cp app:/app/var ./backup-var`).
- **עדכון גרסה**: push ל-branch המחובר (Render בונה לבד) או
  `git pull && docker compose up -d --build` ב-VPS.
- **נעילת כולם החוצה**: מחליפים את `SURVEY_ACCESS_CODE` ועושים redeploy.
